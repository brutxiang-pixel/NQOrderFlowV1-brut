# v6.0 三项实盘安全与研究实现

## 已实现

1. **人工操作/人工平仓闭锁**
   - 检测到当前账户出现非 `OPF|...` 订单时，立即清空所有待确认、回踩、延迟候选及二级槽队列。
   - 若账户已变为 flat、但仍有未完成的 OPF 执行且其保护单已不存在，经过 500ms 二次确认后标记为 `MANUAL_FLAT_DETECTED`。
   - 两种情况都会设置 `LiveReadinessBlocked=ManualInterventionDetected`，本次策略实例不再自动开仓，须停止/启动策略重新对账。
   - 入场异步队列发送前再次检查人工闭锁、账户仓位和 LiveReadiness，避免竞态下的“旧候选再开仓”。

2. **显著区 SZ_RANK_2**
   - 不再将 FVG 类型本身视为显著区成立条件。
   - 必须同时满足结构位移（实体至少 0.35 点且实体/全幅至少 45%）和参与度证据（有成交，且 Delta 不平衡至少 20% 或最大价位成交占比至少 25%）。
   - C 级不进入显著区生命周期；历史账本版本提升为 `SZ_RANK_2`，与旧定义隔离。

3. **显著区与流动性统一决策**
   - 所有执行路径及 Manual Alert 在发送前共同通过 ZoneDecision：反向有效 A 区为硬过滤；同向 A 支撑/压制与上下极值区记录为正向执行证据，但不绕过风险、时段或日损约束。
   - `LIQUIDITY_SPIKE_LABEL` 覆盖每根 M5：相对成交量、Delta 比例、方向、实体和区间均被记录。
   - 当出现相对量至少 2.2、Delta 不平衡至少 45%、且方向明确反向的订单流毛刺时，所有路径和 Manual Alert 都被硬过滤。
   - SetupQuality 增加真实成交流动性组件；分数仍封顶 100，数据缺失不会触发硬过滤。

4. **显著区独立来源**
   - 新增 `ImpulseLiquidity` 来源：不要求 FVG。实体/全幅至少 55%、实体至少 `max(1 点, 0.10 ATR)`、相对量至少 1.5、同向 Delta 比例至少 25%，并且区内存在集中成交，才建立独立显著区。
   - 因此 FVG 现在只是可能的结构线索；强位移与真实主动成交可以独立建立显著区。

## 验证

- `dotnet build OPFStrategyV1/OPFStrategyV1.csproj -c Debug`：通过，0 警告、0 错误。
- 构建前清理了测试项目的旧输出 DLL；未删除任何回测数据或日志。

## 实盘行为

人工修改 TP/SL、人工平仓或手动下单后，策略会进入闭锁并在 HUD/日志中显示 `ManualInterventionDetected`。重新启动策略完成账户与工作单对账后，才恢复自动开仓资格。
